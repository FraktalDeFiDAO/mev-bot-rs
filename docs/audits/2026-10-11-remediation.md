## Implemented locally

- Durable integer micro-dollar transaction ledger, pending liability reservations, retained liabilities across restarts/midnight, stored native valuation and signing address, ownership locks, fsync + atomic rename + directory fsync, and fail-closed corruption/write handling. Startup recovery blocks new admission until every retained transaction is resolved. Signed liabilities survive ambiguous broadcasts and receipt service outages.
- Nonce ownership survives lagging pending counts. AlreadyKnown means the original execution was accepted; transport ambiguity never creates another execution with a fresh nonce. Receipt retry does not clear exposure. First acceptance returns promptly; slower replies are bounded background telemetry.
- Final gas admission uses the submitted gas limit and maximum fee, including priority fee. The sender verifies its signed fee/gas terms against the reserved bound. Gas quotes are integer, recent, asynchronously refreshed, and unavailable/stale quotes cannot authorize sending. Fractional token floors round upward with integer decimal-ratio arithmetic. Estimates do not expand spend caps or count as realized profit.
- Executor accounting preserves pre-existing debt, collateral and native balances. Profit events report transaction deltas. Atlas WETH float cannot subsidize a losing liquidation or be swept as liquidation profit. Contracts remain below EIP-170 runtime size: ArbExecutor 21,376 bytes; AtlasSolver 23,555 bytes.
- Pool revisions and liquidation producer proofs reach the signing/broadcast guard. The guard repeats STOP, confidence, feed continuity and state checks, including after durable attach but before transport. Queued batches repeat admission and reject missing prices/invalid floors.
- Tick/state reads use one canonical block hash. Coherent refresh applies price/liquidity/ticks together and rejects snapshots superseded by events. V4 liquidity changes update both tick boundaries, including inactive ranges and mirrored orientation.
- Subscription precedes full reconciliation; already-covered buffered logs cannot overwrite snapshots. Continuity epochs cannot be reset by summaries. Failed/partial maintenance reads degrade submission confidence until reconciliation succeeds.
- Rule input/token/nesting bounds, SQL value/result/work/time bounds, and two-query concurrency cap.
- Shadow loads endpoint-only credentials, uses separate accounting files and a disposable signer that cannot broadcast. Startup errors and URL userinfo are redacted. A log redactor sanitizes existing local diagnostic logs.
- CI covers workspace Rust, all offline and fork contract suites, browser tests and operator regressions; action refs, Rust and Foundry versions are pinned. Foundry installation failure is no longer ignored. The Seqscope wrapper preserves failed test status. Structured watchdog health rejects unhealthy. Tracked Nitro launcher checks the data mount/import marker; metadata token and region are separate variables. Borrower indexing can shrink below 1,000-block provider limits within its request budget.
- Liquidation DTOs now live in mev-types; bindings no longer depend upward on lending. Engine admission/completion accounting is separated into its own module.

## Verified Atlas source constraint

Atlas V1.6.4 can charge calldata, solver execution and winning-operation overheads to escrow. Its SolverTxResult event does not contain an operation hash or exact per-operation gas charge. Ordinary transaction receipt gas is not an adequate per-solver accounting witness. Settlement must be designed against the actual deployed accounting/relay interfaces and escrow state. Sources read October 11: [Atlas V1.6.4](https://github.com/FastLane-Labs/atlas/blob/main/src/contracts/atlas/Atlas.sol), [events](https://github.com/FastLane-Labs/atlas/blob/main/src/contracts/types/AtlasEvents.sol), [GasAccounting](https://github.com/FastLane-Labs/atlas/blob/main/src/contracts/atlas/GasAccounting.sol). Pin source revisions before treating an integration as production verified.
